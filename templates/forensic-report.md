# Forensic Digital Experience Audit

## Audit manifest
Target, timestamps, mode, rubric versions, source freshness, browsers, viewports, network/device profiles, data integrations and limitations.

## Methodology and evidence coverage
Explain collection, sampling, field-vs-lab data, automated-vs-manual accessibility and source access.

## Site architecture and representative-page coverage
Include template/journey coverage percentages.

## Evidence register
Reference every screenshot/measurement/source/benchmark item used in scoring.

## Award engines
### Awwwards
Raw subdimensions → dimensions → weighted readiness score → caps → confidence.
### Webby
Raw seven criteria. Overall is explicitly internal; no invented official weights.
### CSS Design Awards
UI / UX / Innovation; internal mean; public vote NOT_PREDICTED.
### FWA
Empirical rubric, cohort and calibration confidence.

## SEO Quality
Crawl/indexability, technical, architecture, on-page, intent/content, CWV, structured data/SERP, media, mobile/accessibility-adjacent, trust/spam risk.

## Organic Visibility
State NOT_VERIFIED unless reliable data exists. If connected, specify exact period, device/country population and source.

## Accessibility
WCAG 2.2 checks, levels, automated/manual/not-verified coverage; separate quality score from conformance.

## Performance
Field data first; lab separately. Include CWV and non-CWV diagnostics and budgets labeled official/internal/inferred.

## UX / Design / Motion / Content / Conversion / Engineering
Evidence-backed findings, root causes and trade-offs.

## Resilience / Security & privacy hygiene
No destructive testing. State limits clearly.

## Benchmark Intelligence
Cohort construction, source records, version integrity, medians/percentiles/IQR and sample confidence.

## Pattern mining
Classify REQUIRED / EXPECTED / ADVANTAGE / OPTIONAL / TREND / EXPERIMENTAL / ANTI_PATTERN / NOT_CORRELATED.

## Distinctiveness + Innovation vs Gimmick
No accusation of copying without specific evidence.

## Findings register
One complete record per finding using `schemas/finding.schema.json`.

## Decision roadmap
Severity first; then leverage/impact/confidence/effort. Include validation and regression risk.

## DO NOT CHANGE
Protect high-performing, distinctive and low-cost strengths.

## Regression
If previous audit exists, compare only compatible methods/pages/viewports.

## Calibration / confidence
State corpus, sample size, calibration status and score confidence.

## Machine-readable outputs
List JSON artifact paths.
